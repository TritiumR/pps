# Demo-50 bidirectional ref distillation A/B

## Fixed design

- Source: `data/weight/generated_dataset_50.hdf5`, verified 50/50 successful demos and 14,094 recorded frames. For transfer, both camera streams are deterministically pre-resized with the same `resize_with_pad(..., 224, 224)` used by the model and stored losslessly in six HDF5 shards behind one external-link master; all non-image arrays are copied exactly.
- Observation selection: all 14,094 recorded observations from all 50 demos (`stride=1`), no stage balancing and no simulation rollout. The input transform still receives a fixed-shape demo-action field, so only that unused field is edge-padded at episode tails; teacher targets do not use the recorded demo action chunk.
- Demo-stage selection: eight monotone stages per object (`grasp/lift/carry/place`). Grasp/release boundaries come from the four demonstrated gripper transitions; lift uses the active one-sided lift residual (`0.15 - subgoal_eps 0.12 = 0.03 m` rise); carry-to-place uses the eval criterion (XY distance to `scale_xy + [0, -0.05]` below `0.12`). This selects the active teacher context only; it does not alter teacher cost weights or formulas.
- Teacher cost: unchanged `simple_auth.yaml`. Offline context now supplies the same eight fake-VLM ReKep subgoal/path formulas, held-keypoint semantics, release-on-subgoal context, carry acceleration history/age, object geometry and grasp axis used by active terms. Frame zero precedes rigid-body settling, so fixed plan geometry uses the last 15 frames before the first close. The pear narrow axis and visual fruit half-heights are fixed from the current 20-seed eval perception cache (pear axis mean `[0.6803071, -0.7329272]`; apple axis absent in 19/20); scale-top offset remains `0.05238`. Cost code/config are unchanged.
- Teacher diffusion: no simulation rollout. For each fixed demo observation, MBD runs only in action/diffusion space: 4,096 samples, one iteration, noise 0.4, temperature 0.1, joint delta clip 0.05, executable-action cost, 10 reverse updates plus the final stored label.
- Representation: `demo_delta`, demo mean/std normalization, bidirectional attention, epsilon prediction, 100 training timesteps.
- Cache coverage: K=8 independent Gaussian reverse trajectories per observation.
- A target: cached teacher epsilon. Each optimizer step selects one random cached scheduler level from each of eight distinct trajectories per observation.
- B data target: the final teacher action chunk from the same K trajectories. Training uses standard online Gaussian noising over the 100-step training schedule; its loss target is sampled Gaussian epsilon.
- A/B batch parity: each three-GPU job uses 192 targets globally = 64 targets/GPU. With K=8 this is 24 observations globally = 8 observations/GPU, and all eight trajectories per observation.
- A/B optimization parity: same architecture, seed, optimizer, LR schedule, 30,000 optimizer steps, and observation-level train/validation split. W&B is disabled for remote-run reliability; complete local logs are retained. No observation's trajectories cross the split.
- Evaluation: only ref-only and full-steer, seeds 1-20. Offline teacher-forced/closed-loop diagnostics are intentionally omitted.
- Full-steer keeps the existing trained task proxy `task_eps_bidir_openpi_image_only_demo_meanstd_2gpu_b48/30000`; its norm asset is byte-identical to the no-suffix base-decode asset used for cache generation (SHA-256 `515e84f64a59e10f9618e5a7519ee06572b1757c42ee9aee0bf4f040f3b4cb38`). The no-suffix directory intentionally needs only norm assets for offline teacher decoding and is not substituted for a task-policy checkpoint.
- Evaluation launcher: `tools/run_ref_demo50_eval.sh`; A uses GPUs `0,2,4`, B uses `1,3,5`, first ref-only and then full-steer, with 20 seeds per policy/mode.

## Infrastructure

- Host: six RTX PRO 6000 Blackwell Server Edition GPUs, 97,887 MiB each. DDP preloads the preserved NCCL 2.27.7 runtime and sets `NCCL_IB_DISABLE=1`; the default NCCL 2.26.2 hangs during three-rank initialization on this container.
- Cache generation uses all six GPUs as six demo-disjoint shards. Training uses GPUs 0,2,4 for A and 1,3,5 for B, giving both jobs one NUMA-0 GPU and two NUMA-1 GPUs.
- Local branch: `yixuan-vlm-dev`. Remote existing checkout is updated in place after preserving its pre-existing dirty state.

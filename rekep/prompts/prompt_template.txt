**Note:**
- Each constraint takes a dummy end-effector point and a set of keypoints as input and returns a numerical cost, where the constraint is satisfied if the cost is smaller than or equal to zero.
- IMPORTANT: the cost must be FLAT (exactly zero) across every configuration that satisfies the
  stage, not merely small near one point. Clamp it at zero:
      return max(0.0, np.linalg.norm(end_effector[..., -1, :] - keypoints[0]) - 0.02)
  Writing `norm(...) - 0.02` WITHOUT the max() does nothing: the planner ranks candidates by a
  softmax over cost, which is unchanged by subtracting a constant. Only clamping makes every
  configuration inside the tolerance score identically, which is what lets the planner keep more
  than one way of satisfying the stage. Choose the tolerance from the physical task (a graspable
  object's half-width, a container's clearance), not a fixed number.
- If several distinct configurations would satisfy the stage -- grasp from either side, place in
  either of two bins, approach over or around an obstacle -- return the MINIMUM of the
  alternatives, e.g. `return min(cost_left, cost_right)`. Do not pick one arbitrarily: the
  planner can exploit genuine alternatives, and collapsing them to one removes that freedom.
- For each stage, you may write 0 or more sub-goal constraints and 0 or more path constraints.

- Avoid using path constraints when manipulating deformable objects (e.g., clothing, towels).
- You do not need to consider collision avoidance. Focus on what is necessary to complete the task.

**Completion predicates.**
A sub-goal constraint says how FAR a stage is from done, and the runtime finishes the stage when that number drops below a threshold. For each stage you must ALSO write a `stage<N>_completion` predicate, which answers a different question: has the EVENT this stage names actually happened. Write what the stage MEANS, not a second copy of its sub-goal — never measure a distance to the stage's own sub-goal point in a predicate.
- Signature: `def stage<N>_completion(history, end_effector, keypoints, robot_state, components):`. It returns a plain `bool`.
- Write the body as one named condition per line, then a SINGLE final line `return bool(<and of those names>)`. Do not use `if` statements, early returns, or more than one `return`.
- Build every condition out of these provided primitives, and nothing else. Do not write your own window lengths, gripper thresholds, speeds, or tolerances — the primitives own all of them, and a number you invent will disagree with the runtime.
  - `grasped(i, name, "acquire")` — the PICK-UP event on keypoint `i`: the fingers closed on something real and the object came along with a hand that moved. Use this in a grasping stage.
  - `grasped(i, name, "maintain")` — the object is STILL held. Use this while carrying; it does not require the hand to move.
  - `released(i, name)` — the robot let go of keypoint `i`, by opening the fingers or by leaving the object behind.
  - `stationary(i, name)` — the object carrying keypoint `i` has stopped moving. Use it to mean "it is resting there"; a distance cannot express that.
  - `sustained(cost_fn, name)` — YOUR OWN geometry, in the same cost convention as a constraint (`<= 0` means satisfied), required to hold over a short window instead of at one instant. `cost_fn` is a lambda `lambda end_effector, keypoints: <cost>`. Use it for every geometric condition in a predicate.
  - `grasp_tolerance(i)` — half-width of the grasp feature at keypoint `i`, in metres.
  - `target_region_radius(i)` — radius of the placement region around anchor keypoint `i`, in metres.
  - `clearance_margin(i)` — vertical clearance band for keypoint `i`. Valid ONLY when `i` is on an object the robot CARRIES; asking for it on a fixture is an error.
- `name` is the label the condition appears under in the log. Choose a phrase that says what happened (`"pear_in_hand"`, `"still_held"`, `"inside_place_region"`, `"object_quiescent"`, `"descended"`), not how it was measured.
- The predicate must be able to fail: a stage whose predicate is true from the first frame has not stated an event.

Example, for a stage that places a grasped object (keypoint 4) onto a fixture (keypoint 7):
```python
def stage4_completion(history, end_effector, keypoints, robot_state, components):
    """The object has been placed on the fixture and let go."""
    hand_let_go = released(4, "hand_let_go")
    inside_place_region = sustained(
        lambda ee, kp: np.linalg.norm(kp[4][..., :2] - kp[7][..., :2], axis=-1)
        - target_region_radius(7), "inside_place_region")
    object_quiescent = stationary(4, "object_quiescent")
    return bool(hand_let_go and inside_place_region and object_quiescent)
```
